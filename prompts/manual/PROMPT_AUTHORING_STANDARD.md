# 长提示词编写规范

本仓库的人工提示词必须是可直接复制给 Agent 的完整任务单，而不是只有目标摘要的挑战卡片。默认交付统一为可直接打开的单文件 HTML；如确有必要使用本地 HTTP 服务，提示词必须明确说明，不能改成 Python CLI 或后端项目。

每份长提示词至少包含：

1. Agent 角色与 HTML 交付目标；
2. 浏览器、依赖、单文件内联边界和降级策略；
3. 明确的输入、输出和 window.demo 机器可读接口；
4. 场景或算法的真实状态要求；
5. 固定时间轴、坐标系或状态机；
6. 播放、暂停、单步、重置、seek、自由观察和错误处理；
7. 测试矩阵、边界条件和失败语义；
8. 性能、资源上限和复现要求；
9. 截图/录屏、状态摘要和运行证据；
10. 抗作弊边界、未评测边界和最终回复格式。

写作规则：

- 让 Agent 能直接复制执行，不要求用户在多个文件之间拼接隐含条件；
- HTML、CSS、业务 JavaScript 和 shader 默认内联；外部依赖必须锁定并说明；
- 所有数字、seed、时间、分辨率和阈值都要说明是硬约束还是可调参数；
- 要求真实运行状态，禁止假统计、占位按钮、预录视频和硬编码答案；
- 对历史、灾难、武器等题材保持庄重，不展示血腥细节，不把伤亡做成奖励机制；
- 无法运行或证据不足时必须输出 UNSCORED，不得猜分；
- CI 不评价自然语言风格，只校验机器可读 Schema、评分器和公共骨架；
- 自动化调度、沙箱和结果归档另行定义，不把人工提示词偷偷当成自动化协议。

推荐结构：

一、交付与运行
二、目标与范围
三、输入契约
四、时间轴/坐标/状态机
五、核心实现要求
六、渲染或交互要求
七、交互与 window.demo 评测接口
八、测试矩阵
九、性能与资源
十、证据与复现
十一、抗作弊边界
十二、最终交付格式
